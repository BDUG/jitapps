# markiX · Markup studio

Write Markdown (`.md`) and reStructuredText (`.rst`) in a visual editor alongside
an editable source pane. Open `/markiX/` from the desktop; the app works with the
suite Python server or ordinary static hosting. No parser service, CDN or build
is required for editing.

## Write and edit

- Choose **Visual**, **Source** or **Split** view. Click a heading, paragraph,
  list, code block or table cell to edit it directly.
- Select paragraph/heading text for **Bold**, **Italic**, inline **Code** or
  **Link**. Use the block selector to change heading levels or create a paragraph.
- Add paragraphs, flat bullet lists, code blocks and tables. Select a block to
  delete it. Undo/redo covers typing, imports, templates, format changes and AI edits.
- Navigate through the outline, search/replace source text, or start from meeting
  notes, a project guide or an article. Templates replace the document with undo.
- Name the document in the header. Browser autosave flushes when the page closes;
  storage failures are visible. Invalid stored data is preserved and offered as a
  recovery download instead of overwritten. Export your work for durable backup.

## Source fidelity

The source string is authoritative. Imports and same-format exports keep its
exact characters, including CRLF line endings. An unchanged block is never
rewritten when another visual block changes. Editing a supported block generates
canonical markup for that block; this can change its delimiter style/line endings.
Plain-text paste prevents HTML from running in the visual editor.

Supported visual Markdown: ATX/Setext headings, paragraphs, bold/italic, inline
code, explicit links, flat ordered/unordered lists, blockquotes, fenced code,
horizontal rules and simple pipe tables. Supported visual RST: underlined
headings, paragraphs, bold/italic, literal inline text, explicit hyperlinks, flat
lists, `code-block` directives and the simple `list-table` form generated by the app.

Custom directives/roles, nested lists, references, raw HTML, grid tables, complex
RST options and other unsupported constructs are shown as **source-only** cards.
Use **Edit source** to select their exact source. They are retained in native
exports and AI proposals are instructed to preserve them. This is a deliberately
bounded visual editor, not a full CommonMark/Sphinx renderer. It does not execute
Sphinx directives, includes, raw HTML, embedded scripts or code examples.
Images and some complex inline forms remain source-only. No external parser or
remote rendering service receives a document just by opening it.

The format selector converts supported blocks between Markdown and RST. Cross-format
export uses the same conversion. Documents with source-only blocks are rejected
with an explanation rather than silently dropping or misinterpreting content;
keep their format or convert those constructs manually first. Review converted
markup when exact formatting matters.

## Files and exports

**Open** loads `.md`, `.markdown`, `.rst`, `.txt` (Markdown), or native `.json`.
The filename selects the syntax; importing is undoable. Invalid/oversized files
leave the current document unchanged. Individual uploads accept up to 20 MiB.

**Export** offers original markup, Markdown, RST, native markiX JSON and a safe
HTML reading copy. Source-only constructs appear as escaped code in that reading
copy. **Print / PDF** uses the browser print dialog. The schema download describes
`{format:'markix-project',version:1,name,syntax,source}`.

The shared Workspace provides local/virtual-disk file selection, export destination,
project ZIP import/export with review, revision history, tasks and content exchange.
Google Drive/file sources follow the suite's configured shared file menus. The app
is also included in Tauri desktop staging.

## AI editing

Open the shared AI chat and ask, for example:

> Expand the getting-started section with setup steps and a short example.
> Keep the document's current format, code samples and custom directives intact.

The configured relay receives the current document, selected block/source offsets
and the native project schema. Questions can be answered without edits; complete
proposals stay pending until reviewed and applied. AI Undo restores the previous
native document. Use the suite provider settings; no separate key is stored here.

## Verification

```sh
node --test markiX/model-test.cjs
node markiX/browser-test.cjs
```

The browser check requires Playwright and Chromium. It runs a temporary offline
suite server and mocks the AI provider; no paid model is called. Tests cover exact
source preservation, visual/source edits, import/export, project ZIP, virtual disk,
AI review, autosave/recovery, safe rendering and mobile layout.


## Workspace inventory and capabilities

Use **Workspace → Tool actions** for a heading inventory (including Markdown setext and RST headings), prose whitespace cleanup and final-newline review. Cleanup preserves hard breaks, code/raw blocks and line endings. Filter and export the inventory without changing source.
